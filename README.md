# L76148/moon-ron

A strict, dependency-free RON parser and serializer for MoonBit.

The current implementation provides two independently verified capabilities:
parsing a RON document into a dynamically typed `RonValue`, and serializing
that value back to canonical RON text. Typed deserialization, pretty
formatting, and CLI workflows remain separate follow-up milestones.

## Why RON

MoonBit already has established packages for JSON, TOML, YAML, KDL, and HCL.
RON occupies a distinct point in that space: it keeps Rust-style structs,
tuple variants, enums, options, bytes, and comments while remaining readable
as configuration data. An independent MoonBit implementation makes it useful
for test fixtures, game data, and exchange files generated by Rust services.

## Supported syntax

- Unit, booleans, characters, strings, byte strings, byte characters
- Signed integers, unsigned integers, floats, infinities, and NaN
- Sequences, tuples, maps, named structs, tuple structs, and enum variants
- `Some`, `None`, line comments, nested block comments, and raw strings
- Bounded nesting depth and source-positioned errors

## Use

```text
let value = @ron.parse(
  "Point(x: 1, y: 2, tags: [\"parser\", \"ron\"])",
)
let source = @ron.to_string(value)
```

The root package exports:

- `parse(source, max_nesting_depth?)`
- `to_string(value)`
- `valid(source)`
- `RonValue`, `RonNumber`, `RonPosition`, and `RonError`

Run the bundled example:

```text
moon run cmd/main
```

Run the quality gates:

```text
moon check --deny-warn
moon test --deny-warn
moon fmt --check
```

## Design notes

The parser keeps syntax and semantic conversion separate. `RonValue` is a
lossless-enough generic tree for parsing, inspection, and future conversion.
The serializer emits compact deterministic syntax and keeps numeric type
boundaries across a parse/serialize round trip. Typed decoding will be added
as a separate trait layer instead of complicating either operation.
